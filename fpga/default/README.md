# fpga/default -- THE default acq2 image (`default_top`, Cyclone IV E EP4CE10F17C8)

The product acquisition fabric plus the indexed diagnostic block, per `docs/acq2/05-WORKPLAN.md` s2/s3 and
`docs/acq2/06-TIERS.md` (the v3 tiers; this is **v2.2** = 06-TIERS s7 step 1: the v2.1 datapath plus the
C2-side v3 additions). Pins: `default.qsf` (GENERATED by `tools/portspec/qsfgen.py` from the contract).
Registers: `regs.vh` / `regmux.vh` (GENERATED by `codegen/`, schema `sds1000cml-default` v3, 128 selectors,
VERSION 0x00A3; the build-ID is printed by `make generate` and folds in the RTL digest); the top never
hand-decodes a selector. The lane map: `lanemap_seed.vh` (GENERATED by `tools/portspec/lanemapgen.py` from
`the acq2 analysis branch/lanecal.json`). This README documents what the RTL does beyond the
schema text, the clocking and CDC model, the bring-up facts (DBG layout, lane numbering), the deviations
from the plan, and how to verify.

**v2.2 in one paragraph.** `gpmc_slave` takes the 7-bit selector `{A7..A3, A2, A1}` = `{sel[6:2],
gpmc_a2, gpmc_b1}` (balls A2/B1, R0 report), so every v2 register keeps its 4-aligned selector and the v3
registers take the odd slots; 0x21/0x57 stay undecoded. Live in v2.2: `IL_CTRL.TSRC` (test sources
substituted for the record word in `capture.v`), `DRAIN_START`/`DRAIN_LEN` windows and `OP_REWIND` on the
existing read port (`drain.v`), `DRAIN_STAT.POPS`, `POP_MON`, the read-only `LANEMAP` reporting the baked
map, `OP_STACK_CLEAR` decoded and ignored. Every other v3 register (`DEC_*`, `STACK_*`, `STATUS_B`, `EYE_*`,
`DBG2`, DIAG `PAIR_TRIM`/`IL_DLY`/`SNAP_CTRL2`/`CAL_*`/`PHASE_CNT`/`CAL_STAT`/`CAP_SEL`) is a stub: reads 0,
writes ignored, no strobe (the generated `regmux.vh`); `IL_CTRL` stores only `TSRC`. `PHASE_SEL`/`CAP_STEP`
are retired (06-TIERS s1.7): the top holds both at 0 = the v2.1 reset alignment. **Nothing in the 200 MHz
sample / trigger / commit path changed**; the record writer gained two register stages and one 2:1 mux per
bit (s3 TSRC).

## 2. Clocking and domains

```
M2 (~160 MHz) -> PLL A: ph0 ph90 ph180 ph270 (200 MHz encode phases)   cap_clk (200 MHz, CAP_STEP-shiftable)
              -> PLL B: clk100, clk50 (K2 forward, bus registers)
C2 (~80 MHz)  -> clk: GPMC slave, host registers, drain, DIAG window, snapshot readout, PLL scanclk
```

| domain | logic |
|---|---|
| `cap_clk` | lane pad registers, LANEMAP pipeline, encode divider, decimator, trigger, record write (M9K port A) |
| pair clocks (mux of ph0..ph270) | only the DDIO cells of the encode pairs and their 2-flop re-timing of `{rate3, enable, enc_sdr}` |
| `clk50` | 27-ball bus output/input registers, singles, D2, K2 DDIO, lane/bus monitor window |
| `clk100` | F2/J2 DDIO cells |
| `snap_clk` (mux of clk50/clk100/cap_clk/clk) | the snapshot writer |
| `clk` | everything the host touches; record and snapshot read ports (M9K port B) |

Every crossing: OPCODE pulses `clk->cap_clk` by `sync_pulse`; configuration words are quasi-static and
re-registered in the destination; status bits `cap_clk->clk` by `sync_bit`; `{wrote_count, wr_ptr}` and
the drain read pointer by `sync_word` (a request/acknowledge handshake -- the 20480-deep ring is not a power of
two, so gray codes were not an option); the M2 edge count by `sync_word`; frozen record words (`rec_start`,
`rec_len`, `trig_idx`, `trig_frac`) are read only after DONE. The lane pads, comparator, P6, D1, bus and singles
are declared false paths (calibrated / asynchronous inputs). See the header of `default.sdc`.

**Why the record lives in the capture domain.** The plan's "dual-clock FIFO into the C2 domain" cannot carry
200 MSa/s x 2 channels into an ~80 MHz domain; the fast tier only exists if the M9K ring is written at the
capture clock. The ring itself is the dual-clock element (write on `cap_clk`, read on `clk`).

**Why the lanes are registered on one capture clock** (05-WORKPLAN s3 says "per pair clock"). A per-pair
register on the pair's phase clock has to be re-timed into the capture domain; that transfer is a related-clock
sub-cycle path whose phase changes at runtime (PHASE_SEL mux + CAP_STEP), so STA could never close it and a
false path would hide a real hazard. v2.0 registers all 80 lanes on `cap_clk` (IOE fast input registers) and
gave calibration two knobs: `DIAG PHASE_SEL[7:0]` (per-pair encode phase, 0/90/180/270) and
`PHASE_SEL[15:8] CAP_STEP` (the capture clock in 312.5 ps steps -- 16 per period per the fit report, not
the 208 ps the v2.0 text assumed, 06-TIERS s8.3). **Both are retired in schema v3** (06-TIERS s1.7: PAIR_TRIM
and the static CAP_SEL replace them in v3.0); v2.2 holds `phase_sel = 0` (every pair on ph0) and
`cap_step = 0`, the v2.1 reset alignment that lanecal and the R0 captures ran at. Per-pair capture clocks
are the v3.0 item (WP-F1).

**Encode details.** Rate 3 forwards the pair clock through the DDIO cell (`{1,0}`); rates 0..2 output an SDR
bit `enc_sdr` from a divider on `cap_clk` (period 16/4/2 cycles) re-timed into the pair clock. The per-pair
4:1 phase mux is a LUT clock mux (Quartus warns "clock driven by combinational logic") whose select is the
constant 0 since v2.2 (every pair on ph0; synthesis may fold the mux away). `samp_tick` marks one `cap_clk`
cycle per encode period; its alignment to the ADC's data window is the v2.1 reset alignment (CAP_STEP 0,
the state lanecal and R0 were measured in) until v3.0's static CAP_SEL (06-TIERS s1.2.1).

## 3. Register semantics beyond the schema text

- **RUN.MODE**: 0 = AUTO fires as soon as the pre-trigger depth is filled (free-run, owned-fpga semantics; the
  app implements any AUTO timeout policy); 1 = NORM waits for the condition indefinitely -- the pre-trigger
  history is a wrapped ring and stays intact (no forced "norm bound" as in the prior).
- **PRETRIG/POSTTRIG** are in samples. Dual mode: 1 sample = 1 word. Single-channel modes (CHMODE 1/2): the
  record packs two consecutive samples per word ({first, second}), the counts are converted to words by `>>1`
  at arm time, and the joint clamp is `pre <= 20478`, `pre + post <= 20478`, `post >= 1` (words).
- **TRIGPOS_HI**: `[14:0]` = index of the trigger WORD in the drained record (= pre depth in words when a
  trigger was accepted; = rec_len for an untriggered HALT record). Bit 15 (outside the schema field) = 1 when,
  in single-channel mode, the trigger sample is the FIRST (high-byte) sample of that word -- schema defect,
  see s6.
- **TRIGPOS_LO**: Q16 `(level - s[k-1]) / (s[k] - s[k-1])` for the software trigger; 0 for the A12 trigger.
- **Software trigger**: on the selected channel (TRIG_SRC, or the single channel) with hysteresis TRIG_HYST:
  rising arms at `s <= level-hyst`, fires at the first `s >= level`; falling mirrored. Hardware trigger
  (TRIG_LEVEL.HW_SEL): 3-flop-synchronized A12 edge of the selected slope, sticky until accepted.
- **HALT**: triggered -> finalize on the partial post window (the post count as it stood two writes before
  the halt); untriggered -> a VALID record of the last `min(wrote, 20480)` words with TRIG = 0; in stream
  mode -> stop writing (DONE, not VALID; READY stays 1 while RUN.STREAM is set so the ring can still be
  drained). HALT takes effect one cap_clk after it reaches the capture domain.
- **TRIGPOS_LO** is final ~24 cap_clk cycles (120 ns) after the trigger is accepted, always before DONE can
  have been synchronized into the C2 domain and read.
- **STATUS_A.OVERFLOW** (stream): sticky, set when a write would make the ring look empty to a reader at the
  synchronized read pointer (conservative by the sync latency). Cleared by GO/RESET.
- **FILL**: `wrote_count` (words, saturating at 20480) -- in stream mode the live write pointer.
- **BURST**: reads 0 unless VALID or STREAM; the alias 0x00 pops exactly like 0x40 (regmux). The drain
  address clamps at the last word of the window after REMAIN reaches 0 (flat tail, no re-wrap).
- **DRAIN_START / DRAIN_LEN / OP_REWIND** (v2.2, `drain.v`): the drain covers the logical words
  `[START, END)` of the frozen record, `END = rec_len` when `LEN = 0`, else `min(rec_len, START + LEN)`.
  The two registers are live (read back what was written; `DRAIN_START` keeps `IDX[14:0]`, bit 15 reads 0)
  and are LATCHED at DONE (the rise of the synchronized VALID) and at `OP_REWIND`, which also puts the pointer
  back to START; a write alone changes nothing until the next DONE or REWIND. Reset (0, 0) = the whole
  record = the v2.1 drain word for word. A window starting at or beyond `rec_len` is empty (REMAIN 0, pops
  return the record's last word). Stream mode: REWIND moves the physical pointer to `START mod 20480`.
- **DRAIN_STAT.POPS**: every BURST/BURST_ALIAS pop strobe since GO / REWIND / RESET, 16-bit wrapping
  (underruns included).
- **POP_MON**: `MIN_GAP` = the shortest distance in clk cycles between two consecutive pop strobes since
  GO (255 until two pops happened; ~13 at the 165 ns BFM cadence, 3 at the C2 minimum); `UNDERRUN` = pops
  that found no word since GO (window drained, no record, or stream avail = 0 -- the last word is
  returned), saturating at 255. Cleared by GO and RESET, kept across REWIND.
- **IL_CTRL.TSRC** (v2.2, `capture.v`): 0 = the converters; 1 RAMP, 2 COLTAG, 3 GLITCH substitute the
  16-bit record word at the writer input, after decimation and single-channel packing, with k = the
  writer's word index since GO (continuing across ring wraps in stream mode, identical in every CHMODE):
  RAMP `k & 0xffff`, COLTAG `{k mod 5, (k / 5) & 0xff}`, GLITCH `0xffff` when `k mod 512 == 0` else 0 --
  `iface.TsrcWord` / `ModelTsrc` are the reference (rungs R1, R2b). Change TSRC before GO. The other
  IL_CTRL fields read 0 (v3.0+).
- **ACQ_CTRL** resets to `0x7c00`: encode OFF, all five PAIR_EN bits set, rate 0, so writing ENC_EN alone
  starts every pair at 12.5 MHz. IL_EN is stored and read back but has no effect in v2.0 (WP4).
  RUN.STACK likewise (WP4b). ENV_DATA reads 0 and its pop is ignored.
- **OPCODE**: GO is accepted only while RUN.RUN = 1; any value other than RESET/GO/HALT is ignored (the
  vendor arm/halt words alias here harmlessly).
- **SNOOP_SEL**: `[6:0]` the full 7-bit selector of the last CS1 write (`{A7..A1}`; 0x25 shows 0x25),
  `[7]` A2 and `[8]` B1 sampled with it (= SEL[1] / SEL[0] since v3, kept for the R0 replay), `[15:9]` write
  count. Undecoded writes (0x21, 0x57) are recorded too.
- **MISC_RD[7:6] B1/A2**: the pad levels during the read in progress, i.e. selector bits 0/1 of 0x74 = 0/0
  by construction since v3 (they were free inputs in v2).
- **CLK_STAT.RATIO**: M2 rising edges during a 4096-cycle C2 gate, /16, saturating at 4095 (160/80 MHz -> 512).
- **DIAG_CTRL** resets to `0x0102` (K2 on, F1 = 1). A write with SNAP_ARM = 1 (re)arms the snapshot; the bit
  reads back as written. LANE_GATE_RST is a level: the ever-flags stay cleared while it is 1.
- **DIAG LANE_TOG** is ONE windowed counter on the signal selected by LANE_IDX (65536 `clk50` cycles per
  window, saturating); a reading is valid two windows (~2.6 ms) after LANE_IDX changes. Ever-1/ever-0 flags
  are kept for every monitored signal concurrently. LANE_IDX 0x7b (K2) reports the K2 enable level.
- **DIAG SNAP_MODE 6** packs `{F3 F5 G5 D3, P6, bus 16..26}` (17 sources into 16 bits: F7 is dropped -- s6).
  Mode 7 writes five words per five clocks from ONE coherent lane sample (2048/5 = 409 full samples).
- **DIAG SNAP_CLK**: 0 = clk50, 1 = clk100, 2 = cap_clk, 3 = clk. Change it only while no snapshot runs.
- **DIAG ADC_HOLD**: a held ball drives 1 regardless of BUS_OE/BUS_DRV_EN. Bus balls drive
  `BUS_DRV[i]` iff `DIAG_CTRL.BUS_DRV_EN & BUS_OE[i]` (or held); the bus output and input registers run on clk50.
- **MISC_RD[9] G2** reads the driven G2 level (G2 is an output ball, not a readback pad).

**DBG (0x7c)**: `[1:0]` capture state (0 idle, 1 fill, 2 halt) `[2]` triggered `[3]` valid `[4]` RUN.STREAM
`[5]` cap-clock phase-step engine busy `[6]` phase-step error (sticky until CAP_STEP changes) `[7]` snapshot
ready `[8]` snapshot running `[9]` PLL A locked `[10]` PLL B locked `[11]` encode enabled (cap domain)
`[15:12]` cap-clock steps applied, low nibble.

**LANEMAP** (DIAG 0x10..0x5f) is **read-only since v2.2** and reports `lanemap_seed.vh` = the calibrated
map of all ten cores (`the acq2 analysis branch/`, `LANEMAP_SEED_ID` 0x2611); writes are
ignored, a different map is a rebuild (the RTL digest of the build-ID does NOT cover `*.vh` -- see s6).
Pair layout: entry 16k+b = pair E(k+1) CH1 bit b, entry 16k+8+b = pair E(k+1) CH2 bit b (b = 0 LSB .. 7 MSB).
Dual-E1 mode: CH1 = entries 0..7 (E1 CH1), CH2 = entries 8..15 (E1 CH2); `diag.v` hands cores 0/1 of the
seed to `adc_front` as constants, so its two-stage 80:1 assembler folds to wiring in synthesis (06-TIERS s3.1
credits ~700 LEs). Cores, MSB..LSB lane numbers:

E2: CH1 [76, 73, 77, 74, 78, 75, 66, 67] CH2 [65, 64, 71, 72, 70, 79, 69, 68]
E3: CH1 [8, 10, 9, 12, 11, 14, 13, 15] CH2 [0, 4, 1, 5, 2, 6, 3, 7]
E4: CH1 [31, 28, 30, 27, 29, 18, 20, 19] CH2 [26, 23, 22, 25, 24, 17, 21, 16]
E5: CH1 [47, 44, 45, 35, 37, 46, 36, 40] CH2 [42, 38, 41, 39, 32, 43, 33, 34]

T15 K15 L15 L16 N15 N16 P15 P16 R16; 16-31 L7 N8 P8 R8 T8 M9 M10 M11 N9 P9 P11 R9 R10 T9 T10 T11; 32-47 C16

## 4. Reset posture (05-WORKPLAN s3)

Bus all tri-state except L4/T2/T7 driven 1 (ADC_HOLD = 111); D2 = 0; K2 = 50 MHz on; F1 = 1; G1 = G2 = K1 =
A11 = 0; singles tri-state; F2 = J2 = 0; encode off (ACQ_CTRL = 0x7c00); DECIM = 1; PRETRIG = POSTTRIG =
10240; TRIG_LEVEL = 0x80; RUN = 0; IL_CTRL = 0 (ADC source); DRAIN_START = DRAIN_LEN = 0 (whole record);
POP_MON = 0x00ff. All registers use power-up initial values; there is no reset net.

address` (clk), `g_pair[0].s2[1] -> DDIO cell` (encode phases), `sel[3] -> gpmc_d[10]` (the GPMC read

## 6. Defects found in the plan / references (printed, not absorbed)

1. **05-WORKPLAN s3 "dual-clock FIFO into the C2 domain" vs. "capture write must close at 200 MHz"**: the
   two are inconsistent at 200 MSa/s; the record write is in the capture domain (s2).
2. **Per-pair lane registration** (05-WORKPLAN s1/s3) is not STA-closable with runtime-variable phases;
   v2.0 registers on the capture clock (s2). Per-pair capture clocks are a WP4/WP6 item.
3. **Schema: TRIGPOS_HI has no field for the sample half in single-channel mode**; bit 15 carries it
   outside the schema field (the app must read the raw word).
4. **Schema: DIAG SNAP_MODE 6** lists 17 sources for a 16-bit word; F7 is dropped.
5. **Schema: LANE_IDX 0x7b "K2"** cannot be a toggle count (a 50 MHz output sampled at 50 MHz); it reports
   the K2 enable level.
6. **Schema: ACQ_CTRL reset value** is unspecified; PAIR_EN resets to all ones so ENC_EN alone runs every pair.
7. **Prior art**: the owned-fpga `il_capture`/`capture` split forced a "norm bound" trigger to keep the
   record linear; a wrapped record with `rec_start` removes that limitation (NORM waits indefinitely).
8. **QSF**: `sel` has balls only for A3..A7; the top declares `sel[6:2]` so Quartus never auto-places
   phantom `sel[1:0]` pins (the fit must place 0 unassigned pins, 05-WORKPLAN s4.9). Since v3 the two
   missing bits are the existing `gpmc_a2` / `gpmc_b1` inputs, concatenated in the top.
9. **06-TIERS s2 "DRAIN_START latched at DONE"**: implemented as the rise of the C2-synchronized VALID
   (the frozen `rec_len` has been stable for >= 2 clk by then); a stream-mode HALT (DONE without VALID)
   latches nothing, which is the intent (the window is a frozen-record concept).
10. **06-TIERS s1.6 "a pop on an empty source returns the last word"** in stream mode on the v2.1 ring:
   the pointer still advances unconditionally (commit 6b36253's EDMA prefetch fix) and the pop is counted
   as an UNDERRUN; the word returned is whatever the ring holds at that address. The FIFO-based v3.0 reader
   can hold the last word; the ring cannot without breaking the prefetch behaviour.
11. **Build-ID coverage** (fixed at integration): `codegen/cmd/ifacegen` digested `fpga/common/*.v,
   fpga/default/*.v, *.sdc, *.qsf` and excluded `*.vh`; `lanemap_seed.vh` is consumed by `diag.v`, so a
   re-baked map alone would not have moved the build-ID. `DefaultRTL` now lists `fpga/default/lanemap_seed.vh`
   explicitly (13 digested files).
12. **Stage A (06-TIERS s4 A) loses its actuator on v2.2**: PHASE_SEL/CAP_STEP are gone from schema v3, so
   the data-valid window map must be run on the v2.1 image before v2.2 is deployed, or the schema needs a
   v2.2-only DIAG entry (WP0-v3's open issue; the fabric follows the schema).

**Timing model notes.** The GPMC read through-path (`{nCS1, nOE, sel} -> read mux -> gpmc_d`) is
constrained by `set_max_delay 30` (3 GPMC_FCLK ticks, including the 6 + 5 ns external delays) instead of
the 10 ns virtual-clock relation that can never close; the factory CS1 timing samples 90 ns after nOE
falls (fpga-specs/10 s4.3), and a faster GPMC configuration (WP2) must keep RDACCESSTIME >= OEONTIME + 3.
The prior shipped the same path as an unconstrained "-16.6 ns artifact". Paths between two different
members of the PLL group are false paths pairwise (they exist only through the LUT clock muxes; every real
transfer goes through a synchronizer whose first stage is cut); same-clock paths through the muxes stay
timed, so the snapshot writer is closed at 200 MHz for SNAP_CLK = cap_clk and each encode pair at 200 MHz
for its phase. The 200 MHz pipelining of `capture.v` is described in that file's header: host-visible
behaviour is unchanged except that HALT acts one cap_clk later and a HALT of a triggered record freezes the
post count two writes early (both invisible at GPMC time scales); TRIGPOS_LO is final ~120 ns after the
trigger, i.e. before DONE can have reached the host.
